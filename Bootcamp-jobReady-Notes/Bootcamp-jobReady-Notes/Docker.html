SECTION 1

😩 Why was DevOps even created?

Imagine you built an amazing MERN project on your laptop. Everything works perfectly. You send it to your company. Suddenly...

👨‍💻 Developer

  • Works perfectly
  • Node 22
  • MongoDB Latest
  • npm install done
➡

🖥 Production Server

  • Different Node Version
  • Missing Packages
  • Wrong Environment
  • Application Crashes ❌
Classic Dialogue: "It works on my machine." This single sentence caused thousands of deployment problems before DevOps became popular.

Problem 1

Developer and server have different environments.

Problem 2

Deployment takes hours and is mostly manual.

Problem 3

Developers and Operations blame each other.

Problem 4

Users experience downtime after every release.

Before DevOps, Developers and Operations worked like two separate teams. Both had different goals, which caused delays and deployment failures.

Think Like This Traditional Development is like a relay race 🏃 Developer → QA → Operations Everyone waits for the previous person.

🚀 CI/CD Explained

Whenever you push code to GitHub, a series of automated steps can happen. This process is called a CI/CD Pipeline.

👨‍💻
Write Code
📤
Git Push
🧪
Run Tests
🐳
Build Docker
🚀
Deploy
👥
Users

Continuous Integration (CI)

  • Developers push code multiple times every day.
  • Tests run automatically.
  • Bugs are detected early.
  • No waiting till the end of the project.

Continuous Deployment (CD)

  • Application automatically reaches Production.
  • No manual upload.
  • Deployment becomes faster.
  • Less chance of human mistakes.
Example You push your MERN project to GitHub. ↓ GitHub Actions starts automatically. ↓ Tests pass. ↓ Docker Image is created. ↓ Application is deployed to Render/AWS. ↓ Users see new features.

SECTION 7

🖥️ Virtual Machine vs Docker Container

Both isolate applications, but Docker Containers are lightweight because they share the host OS kernel.

Virtual Machine

  • Includes complete OS
  • Heavy (GBs)
  • Slow startup
  • More RAM usage

Docker Container

  • Shares Host OS
  • Lightweight (MBs)
  • Starts in seconds
  • Efficient
Easy Memory Trick
VM = Complete House 🏠
Container = Apartment 🏢

📦 Docker Image vs Docker Container

One of the most confusing Docker concepts is understanding the difference between an Image and a Container. Don't memorize the definitions. Understand the journey.

Step 1️⃣ Build an Image

A Docker Image is like a snapshot of your application. It contains everything your application needs to run.

Node.js Express Source Code node_modules Environment Everything Required
📸 Think of an Image as a photograph. Everything is captured inside it, but it isn't running yet.

Docker Image is an executable files. Inside it there are instructions how the containers will make.
Image = Blueprint Image = Template Image = Snapshot Image = Package

A Container is your application that is actually running. Unlike an Image, it can execute code, receive requests and store temporary data.

SECTION 11

📝 Dockerfile

A Dockerfile is simply a text file that contains instructions to build a Docker Image. Instead of manually installing Node.js, dependencies, and copying files every time, Docker automates everything.

💡 Think of a Dockerfile as a Recipe.

Recipe ➜ Instructions
Cake ➜ Final Product

Dockerfile ➜ Instructions
Docker Image ➜ Final Product
FROM node:22 WORKDIR /app COPY package*.json . RUN npm install COPY . . EXPOSE 5000 CMD ["npm","start"]

Line by Line Explanation

FROM

Selects the base image.

Example: Node.js 22

WORKDIR

Creates the working folder inside the container.

COPY

Copies project files from your laptop into the container.

RUN

Executes commands while building the image.

EXPOSE

Tells Docker which port your application uses.

CMD

Starts your application when the container runs.

🐳 Docker Compose

Imagine your MERN application has

  • React Frontend
  • Node Backend
  • MongoDB
  • Redis

Running every container one by one becomes difficult. Docker Compose solves this problem.

Docker Compose lets you start multiple containers using just one command.
docker compose up

docker-compose.yml

version: "3" services: backend: image: node ports: - "5000:5000" mongodb: image: mongo ports: - "27017:27017"

Workflow

        ▼

        │

        ▼

Backend Container

MongoDB Container

        │

        ▼

Everything Starts Together 🚀

Why Compose?

  • No multiple commands
  • Easy setup
  • Perfect for MERN Projects
  • One configuration file

Useful Commands


docker compose up

docker compose down

docker compose ps

docker compose logs

Real Example

Companies usually separate Frontend Backend Database Redis Nginx into different containers and start them together using Docker Compose.

Remember Dockerfile → Builds one image. Docker Compose → Runs multiple containers together.
SECTION 13

💾 Docker Volumes

Imagine you stored all your college assignments inside your laptop. Now suddenly your laptop crashes. 😢 Everything is gone. Containers behave exactly the same. When a container is deleted, its data is also deleted. Docker Volumes solve this problem.

Simple Definition A Docker Volume stores your data **outside the container**, so even if the container is deleted, your data remains safe.

Without Volume


Container

┌────────────────────┐
│  MongoDB           │
│                    │
│  Student Data      │
│                    │
└────────────────────┘

docker rm

❌ Everything Lost

With Docker Volume


             Docker Volume
          ┌───────────────┐
          │ Student Data  │
          └──────┬────────┘
                 │
        ┌────────▼────────┐
        │    MongoDB      │
        │   Container     │
        └─────────────────┘

docker rm

Container Deleted

✅ Data Still Safe

🏦 Bank Locker

Money is not kept in your pocket forever. You keep it safely inside a locker. Docker Volume works the same way.

📸 Google Photos

Even if your phone breaks, your photos are safe because they're stored elsewhere. Docker Volume follows the same idea.

💡 Real Use Case

MongoDB MySQL PostgreSQL Redis All databases should use Volumes.

docker volume create mydata docker volume ls docker volume inspect mydata docker volume rm mydata
Always use Volumes for databases. Never store database files only inside containers.
SECTION 14

🌐 Docker Networks

Containers cannot magically communicate. Docker Network allows containers to talk to each other securely.

Without Network 


Frontend

     ❌

Backend

     ❌

MongoDB

No Communication

With Docker Network 


          Docker Network

      ┌──────────────┐

Frontend ⇄ Backend ⇄ MongoDB

      └──────────────┘

All Containers Can Communicate
Think of Docker Network as a Wi-Fi Router 📶 Everyone connected to the same Wi-Fi can communicate.

Bridge Network

Default Network. Containers on the same machine communicate.

Host Network

Container shares Host Machine Network. Very Fast.

Overlay Network

Used in Docker Swarm. Containers communicate across multiple servers.

Common Commands

docker network ls docker network create mynetwork docker network inspect mynetwork docker network rm mynetwork
Real Company Example Frontend Container ↓ Backend Container ↓ Redis Container ↓ MongoDB Container All of them communicate through Docker Network.

Complete MERN Architecture 


               Internet

                   │

             React Container

                   │

         Docker Bridge Network

Container Container Container

When to Use Volume?

When data should survive. Examples: MongoDB MySQL Redis

When to Use Network?

Whenever containers need to communicate. Frontend ↔ Backend Backend ↔ Database Backend ↔ Redis

Interview Tip

Volume stores Data. Network connects Containers. Students often confuse these two.
