AI Agents & Tool Calling

Forget "an AI agent is an autonomous system that..." — just look at what it actually does.

❓ PROBLEM

Every course defines "AI Agent" with a heavy sentence full of words like "autonomous" and "goal-directed." Nobody remembers that sentence a week later.

💡 SOLUTION — Imagine this

You message Swiggy: "Where is my order?" Within 2 seconds, you get a reply: "Your rider is 5 minutes away."

That entire behind-the-scenes process is called an AI Workflow. No long definition needed.

❓ PROBLEM — now the tricky part

You ask ChatGPT: "Book a flight to Goa." ChatGPT cannot book a flight. It has no hands. It can only generate text.

💡 SOLUTION — Tool Calling

ChatGPT calls an outside tool to do the real-world action. Example: it calls Make.com, which calls a real Flight API, which actually books the ticket. ChatGPT then replies with the confirmation.

02

Retrieval, Embeddings & Vector DB

Don't start with embeddings. Start with the question every student actually has.

❓ PROBLEM

Can ChatGPT read your college notes? No. Why not? Because it has never seen your files. It only knows what it was trained on.

💡 SOLUTION — Retrieval

You give the AI a searchable copy of your own documents. When you ask a question, it searches your files first, then answers using what it found. This is called RAG — Retrieval-Augmented Generation.

Embedding — no math, just coordinates

Imagine every sentence turns into a set of coordinates. Sentences with similar meaning land close together on the map.

"Apple is a fruit"  → (2.1, 5.6, 7.4)
"Banana"            → (2.2, 5.7, 7.3)
"Orange"            → (2.0, 5.5, 7.5)

Nearby numbers = similar meaning

Vector Database — a different kind of search

Normal database

SELECT * FROM notes
WHERE title = "AI"

Needs the exact word to match.

Vector database

find("something similar
to AI Agents")

No exact keyword needed. It matches meaning.

🧠 VISUAL — answering a question
Question
↓
Embedding
↓
Vector DB
↓
Nearest Match
↓
Answer
💻 CODE EXAMPLE — the retrieval step, in plain pseudo-code
function answerFromDocs(question) {
  const qEmbedding = embed(question);
  const matches = vectorDB.search(qEmbedding, { topK: 5 });
  const context = matches.map(m => m.text).join("\n");
  return askAI(`Answer using only this context:\n${context}\n\nQuestion: ${question}`);
}

Common vector databases

Pinecone — fully managed, easy to start Chroma — open source, great for small projects Weaviate — open source, built-in search features Supabase (pgvector) — vector search inside normal Postgres FAISS — a library, not a full database, good for learning

03

Workflow Automation & Multi-Agent

One AI call answers a question. A workflow finishes a whole task, end to end.

❓ PROBLEM

A customer emails asking for a refund. Somebody has to read the email, check the order, check the payment, check the policy, and reply. That's five separate jobs for one ticket.

💡 SOLUTION — chain the steps

Instead of one person doing all five jobs, one workflow does them automatically, in order, each step feeding the next.

🏢 INDUSTRY EXAMPLE — Amazon-style refund
Customer Refund Request
↓
AI reads the email
↓
Checks the order
↓
Checks the payment
↓
Checks the return policy
↓
Creates the refund
↓
Sends confirmation email

One workflow. Five checks. Zero humans needed for the simple cases.

🧠 VISUAL — Multi-Agent system
Customer
│
▼

│
├────► Search Agent
├────► Email Agent
├────► Payment Agent
│
▼
Final Response

One "Main AI" doesn't do everything itself. It delegates each piece to a smaller, focused agent — the same way a manager delegates to specialists instead of doing every job personally.

💻 CODE EXAMPLE — chaining steps with a safety check
async function handleSupportTicket(message) {
  const issueType = await classify(message);
  const knowledge = await searchKnowledgeBase(issueType);
  const draft = await draftReply(message, knowledge);

  if (draft.confidence > 0.85) {
    await sendReply(draft.text);   // auto-resolve
  } else {
    await escalateToHuman(message, draft); // safety net
  }
  await logTicket(message, issueType, draft);
}
🎯 INTERVIEW QUESTIONS
  • What is the difference between an AI Agent and a multi-agent system?
  • Why check confidence before auto-sending an AI reply?
  • Why chain small steps instead of asking one big AI prompt to do everything?
  • What should happen when one step in the workflow fails?
🔥 CHALLENGE

05

Mini Project — Build a PDF Chatbot

The smallest real RAG project you can build. Good for a weekend, great for a portfolio.

🧠 VISUAL
Upload PDF
↓
Convert to Embeddings
↓
Store in Pinecone
↓
Ask Questions
↓
Answer Generated

Build steps

  1. Pick one PDF. Something small — a syllabus or a policy doc works well.
  2. Extract the text from the PDF.
  3. Split the text into small chunks, a few sentences each.
  4. Turn every chunk into an embedding.
  5. Store each embedding and its text in Pinecone (or Chroma if you want something free and local).
  6. Build a simple input box where a user can type a question.
  7. Turn the question into an embedding too, and search for the closest chunks.
  8. Send the matched chunks and the question to the AI, and show its answer.
GOOD TO KNOW
Chroma and FAISS are free and run locally — best for a first attempt. Pinecone is managed and scales better once you're happy with the local version.
